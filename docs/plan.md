# My Long Diary - 구현 계획서 (Implementation Plan)

본 문서는 `rfp.md`의 요구사항과 `research.md`의 분석 결과를 바탕으로 "My Long Diary" 애플리케이션의 단계별 구현 계획을 정의합니다.

---

## 1. 개발 환경 설정 및 기술 스택 확정

*   **프론트엔드 (UI/UX)**: React 18, TypeScript, Tailwind CSS
*   **백엔드 (로컬 시스템 제어)**: Rust, Tauri
*   **상태 관리**: Zustand (간단하고 직관적인 전역 상태 관리)
*   **라우팅**: React Router (필요시 도입, 단일 페이지 앱(SPA) 형태 권장)
*   **아이콘**: Phosphor Icons 또는 Lucide React (심플하고 모던한 아이콘)

---

## 2. 단계별 구현 계획

### Phase 1: 기본 프로젝트 스캐폴딩 및 뼈대 구축 (Week 1)
*   **목표**: Tauri 어플리케이션 생성 및 React 프론트엔드 연동, 기본 UI 레이아웃 구성.
*   **작업 내용**:
    1.  `create-tauri-app`을 이용한 프로젝트 초기화 (React + TS 템플릿).
    2.  Tailwind CSS 설정 및 기본 테마(Light/Dark 톤) 변수 정의 (`index.css`).
    3.  앱 메인 레이아웃 구성 (좌측 사이드바, 우측 에디터 영역 분리).
    4.  사이드바 토글 기능 (Distraction-Free 모드) 구현.
    5.  시스템 폰트 우선 적용 및 폰트 변경 테스트.

### Phase 2: 로컬 파일 시스템 연동 및 에디터 기본 기능 (Week 2)
*   **목표**: 로컬 폴더에 1일 1파일(`YYYY-MM-DD.md`) 형태로 글을 쓰고 읽어오는 기능 구현.
*   **작업 내용**:
    1.  Rust(Tauri Command) 측 파일 읽기/쓰기 API 작성 (fs 모듈 활용).
    2.  프론트엔드에서 현재 날짜 기준 파일 로드 및 빈 파일 생성 로직 연결.
    3.  간단한 텍스트 에디터 UI 구현 (`<textarea>` 기반으로 기본 서식(볼드, 이탤릭 등) 없는 순수 텍스트/마크다운 입력에 집중).
    4.  Debouncing을 적용한 자동 저장 (Autosave) 기능 프론트엔드 및 백엔드(원자적 교체 방식) 연동.

### Phase 3: 보안(암호화) 계층 도입 (Week 3)
*   **목표**: 파일 저장 시 암호화 적용 및 로드 시 복호화 처리.
*   **작업 내용**:
    1.  설정 페이지 내 "비밀번호 설정" 기능 추가.
    2.  Rust 측에 AES-256-GCM 알고리즘 기반의 암호화/복호화 로직 구현.
    3.  PBKDF2 또는 Argon2를 사용하여 사용자 비밀번호로부터 암호화 키 파생.
    4.  파일 포맷 정의: `[Salt][IV][Encrypted Payload]` 형태로 기록.
    5.  앱 시작 시 혹은 잠금 상태에서 비밀번호 입력 화면(Lock Screen) 구현.
    6.  (옵션) 향후 외부 환경에서의 복호화를 위한 독립적인 파이썬 복호화 스크립트 작성 준비.

### Phase 4: 기타 부가 기능 및 폴리싱 (Week 4)
*   **목표**: 환경 설정, 디자인 다듬기, 폴더 기반의 일기 브라우징 및 임포트 기능 완성.
*   **작업 내용**:
    1.  사이드바 리스트 뷰 고도화: 저장된 폴더 내의 일기장 목록(날짜별 정렬) 브라우징 기능.
    2.  환경 설정 페이지 디테일:
        *   일기 디렉토리 위치 변경 및 지정 기능.
        *   글꼴 종류 및 크기, 테마 선택.
    3.  기존 일기장 리소스(.txt, .md) 일괄 임포트 기능 (Rust 정규식을 활용한 파싱 탑재).
    4.  전체적인 UI/UX 흐름 피드백 및 성능(스크롤 버벅임, 메모리 누수) 체크.

## 3. 주요 모듈별 책임 및 구조 (Architecture)

### 3.1. Front-end (React/Zustand)
*   `App.tsx` : 인증(잠금 상태) 및 테마 관리의 최상위 루트.
*   `Editor.tsx` : 핵심 텍스트 입력 영역. 텍스트 변경 이벤트 감지 및 타이머(Debounce) 설정 후 Rust로 저장 커맨드 전달.
*   `Sidebar.tsx` : 일기 탐색 및 생성 기능.
*   `Settings.tsx` : 디렉토리 경로, 암호, 외관 설정.

### 3.2. Back-end (Tauri/Rust)
*   `commands.rs` : 프론트엔드에서 호출 가능한 함수 목록 정의 (ex. `save_diary`, `read_diary`, `list_diaries`, `set_password` 등).
*   `crypto.rs` : AES, Argon2 모듈을 포함하는 독립적인 암복호화 블록 처리.
*   `file_system.rs` : 특정 디렉토리 내 `.md` 또는 `.enc` 파일들의 I/O, 디렉토리 스캔, 백업 폴더 전환 등의 실제 OS 리소스 접근부.

## 4. 고려 및 주의 사항 (Constraints & Notes)

*   **데이터 손실 방지**: 파일을 덮어쓰기 전에 기존 파일을 `.backup` 확장자로 임시 저장하거나 원자적인(Atomic) `rename`을 통해 저장 중 프로세스 강제 종료 시의 데이터 유실을 100% 차단해야 합니다.
*   **암호 분실 리스크**: 보안이 강력한 구조이므로 비밀번호 분실 시 복구가 절대 불가능함을 UI 상에 강하게 고지해야 합니다. <- UI의 분위기를 해치지 않은 선에서.
*   **가벼운 에디터**: 에디터 영역에서 수천 줄의 글을 작성하더라도 렌더링 지연이 없도록 DOM 노드를 최소화한 순수 텍스트 영역을 권장합니다.
